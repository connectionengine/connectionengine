# Installation

Connection Engine is a TypeScript pnpm workspace. It publishes three packages:

| Package                            | What it gives you                                                   |
|------------------------------------|---------------------------------------------------------------------|
| `@connectionengine/core`           | The ECS, schema, mutation pipeline, transports, governance. Required. |
| `@connectionengine/local`          | Ed25519 / `did:key` identity + ZCAP capability constraints.         |
| `@connectionengine/ad4m-bridge`    | Wraps a running [AD4M](https://github.com/coasys/ad4m) instance.    |

You always need `core`. You opt in to the other two, according to the identity and transport story that you want.

## Install

```bash
pnpm add @connectionengine/core
# optional:
pnpm add @connectionengine/local
pnpm add @connectionengine/ad4m-bridge
```

## A minimal world

This is the smallest interesting Connection Engine program: one world, one entity, one component.

```ts
import {
  Schema,
  createAnonAgent,
  createEngine,
  createWorld,
  createEntity,
  defineComponent,
  setComponent,
  getComponent
} from '@connectionengine/core'

const Health = defineComponent({
  id: 'Health',
  schema: Schema.Object({
    current: Schema.Number({ default: 100 }),
    max: Schema.Number({ default: 100 })
  })
})

const engine = createEngine()
const world = createWorld({ engine, agent: createAnonAgent('me') })
const player = createEntity(world)
setComponent(world, player, Health, { current: 75 })

console.log(getComponent(world, player, Health)) // { current: 75, max: 100 }
```

Notice three things:

- `defineComponent` is **global**. Once you define a component, every world references the same definition. The SoA typed arrays live on that definition. The per-entity instance records and view bags live on the **engine**, in `engine.componentStores`.
- The schema (`Schema.Object({ ... })`) is the source of truth. It drives the field defaults, the SoA storage decisions, the network encoding, and the SHACL emission.
- `createAnonAgent` is the simplest agent, and it suits solo mode and tests. Use `@connectionengine/local` for signing-aware identity, and `@connectionengine/ad4m-bridge` for AD4M-backed identity.

## Two worlds talking

One world alone does little. Link two worlds with the in-memory transport:

```ts
import { connectInMemory, flushAsync } from '@connectionengine/core'

const a = createWorld({ engine: createEngine(), agent: createAnonAgent('alice') })
const b = createWorld({ engine: createEngine(), agent: createAnonAgent('bob') })

connectInMemory(a, b)

// On 'a':
const scene = spawnPrefab(a, 'scene:main')
const alicePlayer = createEntity(a)
setUID(a, alicePlayer, 'alice', { parent: scene })
setComponent(a, alicePlayer, Health, { current: 80 })

await flushAsync() // drain the microtask delivery queue

// On 'b':
const bScene = getEntityByUID(b, 0, 'scene:main')!
const bAlice = getEntityByUID(b, bScene, 'alice')!
console.log(getComponent(b, bAlice, Health)) // { current: 80, max: 100 }
```

Eight lines, and you have multiplayer. An entity created on one world materialises on the other, with the same UID path, the same components, and the same values.

For the real session protocol — handshake, event-log replay on late join, and disconnect cleanup — see [Peers & Sessions](/networking).

## Running the tests

Verify the install locally:

```bash
git clone https://github.com/connectionengine/connectionengine
cd connectionengine
pnpm install
pnpm --filter @connectionengine/core test
```

The suite covers the ECS, the mutation pipeline, the binary codec, governance, and the lifecycle.
