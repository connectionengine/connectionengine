# Engine

An **Engine** is the ECS runtime container. Per-engine state lives here — bitECS storage, per-component instance/view bags, time. Systems run at the engine level. Multiple `World` objects can coexist inside one engine; they share storage and tick together.

What the engine owns:

- **One bitECS world.** All entities allocated in this engine share an ID space. CE Worlds scope themselves to subtrees inside it via the `BelongsTo` chain rooted at `worldRoot`.
- **Per-component storage.** SoA typed arrays live directly on each `ComponentDefinition` (so `Transform.position.x[eid]` works without any lookup). Per-entity instance maps + view bags for value fields live on the engine in `componentStores`, keyed by `(ComponentDefinition, entity)`.
- **Time state.** `clock`, `frameTime`, `simulationTime`, `fixedTimeStep`, `deltaSeconds`, `accumulator`. The engine ticks; `tickEngine` / `runSystems` drive every world rooted in it.

What the engine does *not* own:

- **Component / Relation definitions** are module-level singletons. `defineComponent({ id: 'Foo', ... })` produces one `ComponentDefinition` object shared across every engine that uses it. Components defined at module load work for any engine that comes or goes — no per-engine registration step.
- **Identity caches** (`nameCache`, `uidOf`, `parentOf`) live as typed extension properties on `UIDComponent` and `BelongsTo`. The extension itself is global; the inner maps are keyed by Engine so two engines in the same process keep their state isolated. Access via the `nameCacheFor(engine)` / `uidOfFor(engine)` / `parentOfFor(engine)` helpers.

CE Worlds are NOT engines. A World is a logical scope inside an engine — see [Worlds & Systems](/worlds-and-systems).

## Always explicit

Every `createWorld` takes an explicit `engine`. You decide what's shared and what's isolated at every call:

```ts
import { createEngine, createWorld, createAnonAgent, defineComponent } from '@connectionengine/core'

// Module-level: registers globally.
const Health = defineComponent({ id: 'Health', schema: /* ... */ })

// One engine per app — the dominant production shape.
const engine = createEngine()
const world = createWorld({ engine, agent: createAnonAgent() })
```

Two worlds inside one engine share bitECS storage + clock + identity caches:

```ts
const engine = createEngine()
const worldA = createWorld({ engine, agent: aliceAgent })
const worldB = createWorld({ engine, agent: bobAgent })
```

Two engines means full isolation — entity IDs, time, and identity caches all separate. Multi-peer test harnesses use this pattern to simulate independent machines:

```ts
const worldA = createWorld({ engine: createEngine(), agent: aliceAgent })
const worldB = createWorld({ engine: createEngine(), agent: bobAgent })
```

## Extension state on definitions

Identity caches are an instance of a broader pattern: components and relations can carry arbitrary typed extension properties on their definitions. Anything you put on the options object (beyond the reserved keys) lands on the resulting definition with its type preserved.

```ts
import type { Engine, Entity } from '@connectionengine/core'

export const UIDComponent = defineComponent({
  id: 'UID',
  schema: Schema.Object({ value: Schema.String({ default: '' }) }),
  // Typed extension — keyed by Engine so each engine keeps its own buckets.
  nameCache: new WeakMap<Engine, Map<Entity, Map<string, Entity>>>(),
  uidOf: new WeakMap<Engine, Map<Entity, string>>()
})

// Anything else can do the same. Use WeakMap<Engine, ...> for per-engine
// state, or a plain Map / object for genuinely process-global indexes.
```

Reserved component option keys: `id`, `label`, `schema`, `sync`. Reserved relation keys: `name`, `sync`, `exclusive`, `autoRemoveSubject`, `store`, `onTargetRemoved`. Everything else flows through.

## What's on the engine — at a glance

```ts
interface Engine {
  readonly bitECS: bitecs.World                                    // entity ID space
  readonly componentStores: WeakMap<ComponentDefinition, ...>      // per-(component, entity) instance + view bags
                                                                   // (SoA arrays live on the definition itself)

  clock: Clock                                                     // injectable
  frameTime: number; simulationTime: number
  fixedTimeStep: number; deltaSeconds: number; accumulator: number
}
```

You almost never touch these fields directly. Most engine state is accessed through `defineComponent`, `defineRelation`, `getComponentById(id)`, `setComponent(world, e, def, value)`, etc. The fields are public so plugin code and tooling can introspect.
